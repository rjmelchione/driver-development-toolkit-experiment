# Decision Log - Codex Run 02

| Decision | Context | Options Considered | Selected Option | Rationale | Risk / Tradeoff |
|---|---|---|---|---|---|
| Use Python with uv as the project foundation. | Preferred stack is Python, uv, GitHub, Windows. | Python/uv; Rust; Node.js; web-only app. | Python/uv. | Matches experiment constraint and supports data analysis libraries well. | Some high-performance telemetry parsing libraries are Rust-native; may rely on Python bindings. |
| Prefer existing `.ibt` parser over custom binary parsing. | Product requires iRacing `.ibt` support. | Custom parser; `libibt`; `pyirsdk`; Rust/Node parsers through wrappers. | Start with `libibt` if installation validates locally. | Direct Python library for reading IBT files; returns PyArrow tables usable by Pandas-style analysis. | Newer dependency with Rust core; installation may require wheels or Rust toolchain. Fallback may be required. |
| Build the first MVP as a local command-line/report generator before a richer UI. | Vision says application and coaching-first UX, but no UI platform requirement is specified. | CLI/report; desktop GUI; web app; notebook. | CLI/report first. | Fastest maintainable path to prove telemetry ingestion, analysis, ranking, and evidence traceability. Keeps UI complexity from obscuring the coaching engine. | Less polished UX than the long-term product; should be documented as first milestone, not final UX. |
| Model analysis as a pipeline with separate ingestion, lap modeling, opportunity detection, coaching, and reporting layers. | Maintainability and traceability are first-class requirements. | Single script; layered modules; plugin framework. | Layered modules. | Keeps telemetry parsing, domain calculations, recommendation rules, and presentation independently testable. | Slightly more structure than a throwaway MVP, but justified by maintainability goals. |
| Use rule-based explainable coaching for the MVP. | Recommendations must be traceable to evidence and explainable. | Rule-based heuristics; ML model; LLM-generated coaching; opaque statistical model. | Rule-based heuristics. | Supports evidence-backed recommendations and avoids opaque conclusions before a data corpus exists. | Coaching may be conservative and less nuanced; rules should be documented and tested. |
| Proceed with synthetic telemetry fixtures until real Late Model `.ibt` data is available. | Human clarified no representative `.ibt` file is currently available. | Block implementation; use synthetic fixtures; seek external telemetry files. | Use synthetic fixtures for analysis tests and keep `.ibt` ingestion behind an interface. | Allows development of maintainable analysis behavior without inventing file-specific facts. | Real parser integration remains unvalidated until a representative file is supplied. |
| Accept CLI-generated Markdown/text report as first user-facing milestone. | Human confirmed UI can be deferred. | CLI report; desktop GUI; local web UI. | CLI-generated Markdown/text report. | Prioritizes correctness, explainability, maintainability, traceability, and testability. | Less polished than final application UX. |
